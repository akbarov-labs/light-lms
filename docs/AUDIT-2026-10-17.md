# lms-light — independent audit, score and improvement plan

Date: 2026-10-17 · Commit audited: `69c7417` · Method: gates re-run locally + four independent reviewers (billing engine; salary/payments/Payme/reports; security & tenancy; performance/architecture/ops), each finding re-checked against the code. "Confirmed" = reproduced with a probe script or verified line-by-line; "plausible" = strong code-path evidence, not reproduced.

## 1. Verdict

**Overall: 7.4 / 10 — a strong, honest MVP. Ready for a supervised pilot after a 2–3 day fix sprint (Phase 0 below).**

The money core is well designed: billing is "expected vs posted", idempotent and self-healing, and no reviewer found a way to leave a balance permanently wrong. Tenant isolation is consistently enforced. The README's claims check out (typecheck, lint, 170/170 unit tests, `npm audit` 0). The gaps are at the edges — input parsing, a few money edge paths, the worker's queue/jobs, a handful of permission/identity holes — and almost all are cheap to fix.

## 4. Improvement plan

Each item: fix + regression test in the same commit; money fixes stay in `src/lib/billing` / `src/lib/salary` (CLAUDE.md rule 4); decisions appended to `DECISIONS.md`.

### Phase 0 — before the first pilot center (≈2–3 days)

Goal: no wrong money, no privilege escalation.

1. **B1** `parseMoney`: accept `,`/`.` + 1–2 trailing digits only if they are zero (`300 000,00` → 300 000), reject otherwise; table test with ru/uz/en formats; apply to import + pay page. Add a "large amount" confirm on payments > 10× family's monthly charge.
2. **B2** `lessonValue`: key the lesson to the installment due at the lesson's date (or require all installments due up to that date paid); test with the seed's 4-installment course.
3. **S1** Platform admin by user id or DB flag (`User.platformAdmin`), not phone; fix README example.
4. **S2** Filter `DEFAULT_PERMS[role]` through `grantable`; test that a manager without `export` cannot create an admin with `export`.
5. **S3** On guardian/staff/student phone change or archive: clear `telegramChatId` + delete matching `TelegramLink`; bot refuses disabled centers.
6. **R1 + R2** Notification claim with `SKIP LOCKED`; per-item isolation in nightly steps. Integration tests: two concurrent `processNotifications` send each row once; a corrupt group doesn't block billing.
7. **B4** Copy `termsHistory` (minus `priceOverride`) on transfer; engine test.
8. **B7** Cap refunds at available credit unless `force` with reason; allocation turns a negative final pool into a debt unit; property test for the balance invariant (fast-check or seeded random).
9. **S5, S7, S10** quick fixes (control-char reject / origin compare; `assertNotDemo`; generic health error).

### Phase 1 — pilot hardening (≈1 week)

10. **B3** Count not-yet-generated slot dates in both numerator and denominator (reuse `scheduledInPeriod`), or block ACTIVE start dates beyond the generated horizon.
11. **B5** Import idempotency: match existing student by (family phone, first+last name) and existing open enrollment; dry run reports "already exists".
12. **B6, B9, B10** No base pay after `archivedAt`; block paying ≤0 payslips; warn when a rule's `validFrom` isn't the 1st.
13. **R3, R4** 429/`retry_after`, `nextAttemptAt` backoff, unlink on 403; `noOverlap` + advisory job locks.
14. **R5** Payme: allow parallel wallet transactions (drop −31099 for this account type after checking Payme docs), unique `paymeKey`, center-match assertion. Then run the full Payme sandbox test suite with real test keys.
15. **S4** Dev compose: bind `127.0.0.1:${WEB_PORT}`, refuse the example secret on any non-localhost host; trust XFF only behind a configured proxy.
16. **O1, O3** Worker bundle + healthcheck + graceful stop; `error.tsx` / `loading.tsx` / `not-found.tsx`.
17. **B11–B14, S6, S8, S9** small fixes.

### Phase 2 — scale & optimisation (≈1–2 weeks, before ~10 centers or ~1 000 students/center)

18. **P1** Debtors/aging/reminders in SQL with pagination; then `FamilyBalance(familyId, balance, oldestUnpaidDate)` maintained in the ledger-write transaction (keep `SUM(ledger)` as source of truth + nightly reconciliation check).
19. **P2** Revenue/month aggregates in SQL.
20. **P3** Nightly billing batched per group with bounded concurrency; log per-center timings.
21. **P4, P5, P6** Trigram indexes, audit partial index + retention, array fixes. Add `LedgerEntry(lessonId)`, `Enrollment(endDate)` indexes.
22. Re-run `scripts/scale-test.ts` at 10 000 students/center and 50 centers; record numbers in DECISIONS.

### Phase 3 — quality & maintenance (ongoing)

23. Tests for worker jobs, queue, bot data layer, search, debtors/reports queries; add `@vitest/coverage-v8` with a floor (e.g. 80% on `src/lib/billing`, `src/lib/salary`, `src/lib/payments`).
24. One `src/lib/env.ts` (zod) for all env vars; extract duplicated queries (Q1); fix `npm run seed`; `.dockerignore` (O2); pin base images (O4).
25. Dependency majors, one per PR with full gates + e2e: Zod 4 → Prisma 7 → Next 16 → Vitest 5 / ESLint 10.

### 6.3 What still keeps it below 9
- **Scale:** debt aging and the debtors list still run FIFO allocation per view, in 500-family batches.
  - A cached per-family balance plus oldest-unpaid date, updated in the ledger transaction, is the next step past about 10k students per center.
  - Nightly billing is concurrent but not batched per group.
- **Untested surfaces:** the Telegram bot handlers (`worker/bot/index.ts`), and `proxy.ts` outside the browser tests.
- **Not verified live:**
  - the bot with a real token;
  - Payme against its test cashbox, including fiscal `detail`; `SetFiscalData` is not implemented;
  - a real domain with Let's Encrypt.
- **By design, document it:** without `TRUST_PROXY=true` (anything other than the prod compose), all clients share one login rate-limit bucket.
- **Deferred lint:** 10 React Compiler lint findings, which don't change behaviour while the compiler is off.
- **Product gaps** (see the feature roadmap discussion): Click/Uzum, parent announcements, monthly progress reports to parents, at-risk students, admin tasks, cash-desk reconciliation.
